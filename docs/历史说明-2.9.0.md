## 2. 本次改动清单

### 2.1 目录比对并入「文件传输」页

**原来的问题**：比对和传输是两件事、两个页签。用户的真实动作却是连贯的 ——
「看看差多少 → 决定往哪边搬」。拆成两页意味着：看完成果要切页、切页后还得重新勾选一次目标，
中间还要记着刚才的差异清单。差异越大越容易弄混方向。

**现在**：

* 页签从 5 个减到 4 个（文件传输 / 传输列表 / 设置 / 目录绑定）；老 localStorage 里存的
  `tab: "compare"` 会被兜底到 `"transfer"`，不会白屏。
* 「文件传输」页顶部多了一条**比对条**：`[本地] 路径 ⇄ [云端] 路径 [深度] [比对]`。
  路径**自动跟随两栏的浏览位置**；用户一旦手填就停止自动覆盖（不然手填的值会被下一次进目录冲掉）。
* 中栏除了原有的「上传 →」，多了一个 **「比对 ⇄」**：用两栏**各勾选一个文件夹**（各栏只勾一个时以它为准），
  都没勾就按「当前所在目录」。两种习惯都成立。
* 比对条与差异面板都在传输页，**比对完直接就能开搬**，不用切页、不用重勾。

### 2.2 差异从「四分类」变成「三组面向操作的差异」

**原来的问题**：旧结果是「未上传 / 大小不一致 / 已上传 / 云端独有」四类，
其中「已上传」是**没有动作**的信息，「云端独有」标着「仅展示，不处理」——
用户看到云端多出一堆文件，却没有任何下手的地方。

**现在**：`split_diff()` 在原有四分类之上，给出**面向操作的顶层差异**：

| 分组 | 含义 | 这一组给的动作 |
|---|---|---|
| `localExtra` | **仅本地有** | 上传到云端 · 清除本地 |
| `cloudExtra` | **仅云端有** | 下载到本地 · 清除云端 |
| `mismatch` | **两边都有但大小不一致** | 用云端覆盖本地 · 用本地覆盖云端 |

每组带 `xxxCount` 与 `xxxBytes`，界面直接画出「N 项 · 3.2 GB」。

**关键设计：父子归并**（`_prune_descendants`）。差异列表里如果一个目录已经是差异项，
它的子项就**不再单列** —— 因为「这个目录是差异」本来就意味着「整棵子树都是差异」。
不归并有两个实打实的危害：

1. **批量清除会把同一棵子树删两遍**（第二遍必然报「不存在」），用户看到一堆莫名其妙的失败；
2. **批量入队会把整棵树重复排队**，任务列表里出现几十倍的冗余条目。

界面上的具体表现：单个文件的行动作是「上传 / 下载 / 清除 / 覆盖」；
目录差异行只给「整目录」动作，子项由后端递归展开，不在界面上铺开。

### 2.3 批量操作与单行手动操作

差异面板的每个分组标题上就是批量按钮：**全选上传 / 全选下载 / 全选清除**，
作用范围是**该组里已勾选的行**（勾选状态由每行左侧的复选框控制，行内任意位置点击也能切换）。
同时每一行都有自己的动作按钮，做单点处理。**操作成功后该行自动从差异列表摘掉**，
不用重比对——但想彻底核准的话，随时可以再点一次「比对」。

批量清除会弹**二次确认**（列出条数与影响），逐行清除不弹（避免点一下弹一次）。
这是刻意的取舍：批量是"一次性影响很多文件"，值得多问一句；单行是明确指向性操作，多问反而烦。

### 2.4 新增下载能力（云端 → 本地）——本版首次打通反方向

此前应用只能往上走。下载的难点不在"把字节搬过来"，而在**中断时不要留下一个看起来正常的坏文件**。
所以 `download_to_file()` 钉死了三条规则：

1. **写临时文件再改名**：先写 `<目标>.ddpart`，**校验通过**才 `os.replace` 到最终路径。
   直接写目标路径的话，中断会留下半截文件，而它的大小恰好可能"看起来正常"，
   下一次比对就会把它当成已下载 —— 这是最恶劣的一类静默数据损坏。
2. **续传要看服务端脸色**：带了 `Range` 但服务端回 `200`（不支持 Range），
   必须**清空重写**：否则会把整份内容追加到半截文件后面，得到一个「大小翻倍」的文件。
   只有服务端回 `206` 才走 `append`。
3. **大小必须核对**：`Content-Length`（或比对给出的云端大小）与实际写入字节不一致就报失败，
   绝不把残文件当成功。

另外两点：

* **跨源不泄漏 token**：`raw_url` 常常是网盘给的**第三方直链**。只有它与 OpenList
  **同源（host + 有效端口）**才附带 `Authorization`；外站请求一律不带 —— 既没用，又是一次凭据泄露。
* **相对地址用 base_url 补全**：`fs/get` 返回的 `raw_url` 可能是 `/d/xxx` 这种相对形态，
  必须用**OpenList 自身的 base_url** 去拼，拿请求里的 `Host` 去拼会在网关转发场景下拼到应用自己的地址上，直接 404。

**下载队列**（`download_queue.py`）直接**继承**上传队列：持久化、重启恢复、指数退避重试、
暂停 / 取消 / 清除已结束，这些机制与上传**完全同构**，抄一份只会多一份要同步维护的代码。
只覆写两处：入队时打 `direction="download"`（且允许本地目标尚不存在 —— 基类会 `stat` 源文件，
而下载时"源"在云端、"目标"还没创建，那次检查必须跳过），以及把「PUT 上传」换成「GET 流式下载」。

### 2.5 新增清除能力与它的安全边界

**清除是应用里唯一的不可逆操作**，所以边界写得比功能多：

* **云端删除**由 OpenList 执行，**目录是递归删除**；是否进回收站取决于 OpenList 存储驱动的配置，
  应用不做任何保证。批量删除**按父目录分组**发请求（动辄几百项，逐条发是几十秒的差别）；
  整组失败时**降级为逐条删** —— 一条坏条目（比如已被别处删掉）不该拖垮同组其它条目，
  而且逐条才能给出精确的失败原因。
* **本地删除**受**存储空间白名单双重约束**：白名单以外的路径一律拒删；
  白名单根目录（如 `/vol1`）本身也拒删（`rmtree('/vol1')` 是灾难级误操作）。
  逐条独立处理，一条失败不影响其余，并把原因带回前端。
* **每一次删除都写审计日志** `audit.log.jsonl`（append-only），记录
  `at / event / count / paths / failed`。事后至少能查「什么时候、删了哪些路径」，
  而不是只剩界面上一句「已删除」。
* `.ddpart` 临时文件被**永久排除**（`ALWAYS_EXCLUDES`），不受用户排除规则影响：
  它不参与比对，也不会出现在任何一侧列表里 —— 否则下载中的临时文件会被当成"云端多出来的文件"。

### 2.6 上传与下载共用一张传输列表

上传任务和下载任务合并进同一个 `/api/upload/list`，靠 `direction` 字段区分渲染
（图标、第二行显示的路径、按钮文案「重下」/「重传」都不同）。

理由很直白：用户心里的「传输列表」就是**「我让它干的活」**。分成两个页面看，
反而要多点一次才能确认"我刚才那条下完了没"。
`/api/upload/<retry|cancel|remove|pause|clear>` 这些动作接口通过 `find_transfer(task_id)`
在两条队列之间路由，前端不需要知道自己操作的是哪条队列。

### 2.7 顺带修掉的一处死代码

反向验证时发现 `remove_many()` 里的守卫写成了 `if not p or p == "/":`，
而 `p` 已经过 `.rstrip("/")` —— `"/"`、`"//"`、`"\\"` 都会先退化成空串，
所以 `p == "/"` **永远不可达**。已合并为 `if not p:` 并加注释说明。
这不是 bug（行为完全一样），但一条不可达的分支会让后来的人误以为它管着什么。

### 3.3 端到端冒烟 —— 73 项，全绿

从 **2.9.0 的 fpk 解出来的代码**起真实 TCP 服务，对着一个**真正走 HTTP 的假 OpenList** 跑完整链路。
假 OpenList 会**严格校验请求形状**（URL 拼错、认证头不对、字段名写错立刻记入 `BAD`），
下载部分给它加了真实字节与 `Range` 支持：

登录（校验用的是 64 位 StaticHash、凭据无明文）→ 列目录 → 诊断 → 双向比对 →
真实上传队列传文件 → 绑定创建/扫描/上传 → 任务成功后回云端核对 → **任务查不到时不得误判成功** →
源目录读不到时如实报错 → 配置收敛 → 落盘合法 → **本轮新增的 6 段**：

| 新增段 | 断言要点 |
|---|---|
| **[14] 双向比对** | 三组顶层差异都返回；三组各自精确到文件名；大小一致的文件不进任何组；计数与列表长度一致；字节数是数字 |
| **[15] 下载云端多出的文件** | 任务到达终态 `done`；`direction == "download"`；**本地真的落盘**；**下载内容与云端逐字节一致**；不留 `.ddpart` |

## 4. 刻意保持不变的行为

功能扩展时最容易顺手把语义"扩展"掉。以下这些**故意没动**，并且**每一条都有测试钉住**：

1. **绝不自动删除任何文件**。「清除」必须在用户显式点下且（批量的）二次确认之后才执行；
   没有任何定时、扫描、同步流程会触发删除。「目录绑定备份」依旧只增不删。
2. **比对本身是纯只读的**。`POST /api/compare` 不改动任何一端的文件，
   改动只发生在用户点了「上传 / 下载 / 清除」之后。
3. **扫描失败绝不吞掉**：某个目录列不出来时照样 `raise`，**不得悄悄少扫一层** ——
   少扫的那层会被判成「仅本地有」，属于谎报。
4. **「列不出目录」≠「云端确实没有」**：前者沿用上次结论或判「待处理」并写明原因；
   后者才判差异。两者混同会导致无意义的重复上传或漏报。
5. **两边必须用同样的递归深度**：深度不齐会把整棵子树误判成差异，
   所以深度在扫描前统一收敛成同一个值。
6. **凭据只存 StaticHash，不存明文密码**；token 用**裸值**放 `Authorization` 头（不加 `Bearer`），
   这是 OpenList 的约定；**下载的跨源直链不带 token**。
7. **不暴露 TCP 端口**，只走统一网关 unix socket。
8. **`manifest` 里 `appname` 与 `desktop_applaunchname` 未动**，保证覆盖升级而不是并存。
9. **队列 / 绑定 / 配置的磁盘文件与 JSON 结构向后兼容**：旧数据可直接读入；
   新增文件（`download_queue.json`、`audit.log.jsonl`）缺失时不报错。
10. **已有的 HTTP 接口路径与请求/响应字段全部未改**，只**新增**了 3 条路由、
    并给 `/api/compare` 的响应**新增**了 `localExtra` / `cloudExtra` / `mismatch` 等字段
    （旧前端忽略即可）；`/api/upload/enqueue` 的响应新增 `dropped` 字段。
11. **上传链路的语义一字未动**：分片断点续传、完成后回查云端大小、跳过已存在、指数退避重试，
    全部照旧（下载只是复用了这套机制，没有反过来改动它）。

## 5. 已知边界与本次未做的事

1. **跨源直链下载未在真机上验证过**。本版对「同源带 token / 跨源不带 token」有单元测试钉住，
   但从**第三方网盘直链**下载这条路径（例如某些驱动返回 `https://cdn...`）
   没有在真实 NAS 上跑过。如果遇到下载失败，任务详情里会写明原因（多为「云端没有提供下载地址」）。
2. **比对只按大小，不按内容**。两边同名的两个文件只要字节数相同就判「一致」，
   不会去比哈希 —— OpenList 的 `hash_info` 依赖具体存储驱动，不可靠。
   所以「看起来一样却报大小不一致」通常是两边版本确实不同；反过来，
   「大小一样但内容不同」本版**发现不了**。
3. **清除是不可逆的，应用不提供撤销**。云端能否进回收站取决于 OpenList 存储驱动的配置；
   本地删除是直接 `rmtree` / `unlink`。审计日志只记录「删了什么」，**不能把文件找回来**。
4. **差异清单不会自动刷新**。搬完一项后该行会从列表摘掉，但如果你在别处（NAS 文件管理器、
   OpenList 网页）动了文件，需要重新点一次「比对」。自动轮询比对在大库上代价太高（每次都是一次全量扫描）。
5. **目录差异只在界面上呈现为一行**，不铺开子项（见 2.2 的父子归并）。
   想看具体哪些子文件有差异，需要单独比对那个子目录 —— 这是刻意的：铺开会让批量操作重复计数。
6. **「镜像同步」与「移动」仍未实现**。本版只做了「比对 + 逐项搬运 + 逐项清除」，
   没有做成「让两边完全一致」的一键同步 —— 后者需要一个干跑预览和整体确认流程，属于另一个量级的功能。
7. **并发数不是越高越好**。默认 8 是「内网 OpenList」的稳妥值。如果 OpenList 在远端、
   或它挂载的网盘有严格限流，把「扫描并发数」调小（2~4）会更稳。下载队列复用「同时上传数」，
   下载和上传同时跑时总并发是两者叠加。
8. **前端未做 i18n**，仍为简体中文。

```bash
python3 _work/mutcheck.py
```

八条经验，写在这里免得下次再踩：

- **「测试全绿」不是证据，「能变红」才是。** 本版新增了反向验证脚本：
  改坏一处分支 → 跑对应测试 → 必须失败。第一次跑就抓到了一处不可达死代码（见 2.7）。
- **mock 传输层只按 path 匹配会掩盖 URL 构造 bug**。`test_download.py` 里的关键请求
  断言的是**完整 URL**（含 `base_url` 前缀），而不只是 path ——
  曾经有个 `base_override` 的坑就是这么漏掉的。
- **下载的续传必须断言「起始偏移」**，不能只断言"文件最后大小对"。
  本轮冒烟里假 OpenList 会记录收到的 `Range` 头并断言它是 `bytes=100-`；
  只比对最终内容的话，「全量重下」和「正确续传」得到的结果**完全一样**，测不出区别。
- **写临时文件再改名这条规则，测试要覆盖"取消"**：
  取消时必须**保留** `.ddpart`（下次才能续传），而**失败**时不能把它当成目标文件。
  `test_download.py` 里 `test_cancel_keeps_part_file` 钉的就是这个。
- **假服务端的目录删除必须也做递归**：不然删掉目录后子目录的 key 还在，
  下一轮 `list` 会读到幽灵目录，比对结果跟着错，而测试会给出**错误结论**。
- **本机 Windows 环境的 `os.symlink` 会静默降级成普通空文件**（不抛异常、`islink` 返回 False）。
  涉及符号链接的用例要**二次 `skipTest`** 兜住；真机是 Linux，那条路径是真跑的。
- **本沙箱里删文件极慢**（一次 `unlink`/`rmtree` 约 3.2 秒，安全护栏）。
  测试的 `tearDown` 里不要写 `shutil.rmtree` —— `test_download.py` 曾因此从 0.66 秒涨到 64 秒。
  项目里其它测试同样不清理临时目录。
- **查询参数经 `parse_qs` 解析后值是数组**，`(query or {}).get("id")` 拿到的是 `["bd_xxx"]`。
  全项目用 `_arg(query, "id")` 取首值，只有 `/api/bindings/progress` 漏过 ——
  后果是它恒定返回 `progress: null`，而**这种失败是静默的**。冒烟里已补「真 HTTP 按 id 命中」的断言。

## 8. 结论

- **本版把「看差异」和「搬文件」合成了一件事**。目录对比不再是独立页签，而是传输页的一部分：
  两栏各勾一个文件夹 → 点「比对」→ 差异分「仅本地 / 仅云端 / 大小不一致」三组直接呈现 →
  每组可全选上传、全选下载、全选清除，也可逐行手动操作。差异行上带着方向明确的动作，
  不再有「云端独有：仅展示，不处理」这种看着干着急的状态。
- **本版首次打通云端 → 本地**。下载队列直接继承上传队列，复用成熟的持久化 / 退避重试 /
  暂停取消机制；下载本身钉死三条规则（写临时文件再改名、服务端忽略 Range 时清空重写、
  大小必须核对），杜绝"留下一个看起来正常的半截文件"这类静默数据损坏。
  跨源直链不附带本站 token。
- **清除是唯一的不可逆操作，所以边界写得比功能多**：本地删除受存储空间白名单双重约束
  （越界拒删 + 根目录本身拒删），批量清除必须二次确认，
  每一次删除都追加写入 `audit.log.jsonl`。**不存在任何自动删除路径**。
- **差异模型做了父子归并**，避免批量删除删同一个子树两遍、批量入队出现几十倍冗余。
  这是"看起来很细节、实际影响很大"的一处设计。
- **测试规模**：2.8.5 的 528 项 → 2.8.6 的 534 → 2.8.7 的 538 → 2.8.8 的 572 → 2.8.9 的 580
  → 本版 **696 项**（Python 299 → **362**，前端 281 → **334**），端到端冒烟 40 → **73** 项，
  打包自检 50 → **51** 项。本版新增 **116 项**回归断言，专钉这次的新能力与其安全边界。
- **新增了反向验证这一层**：17 条变异全部被测试捕获（0 条存活）。
  它当场抓到一处不可达死代码，说明这层不是形式主义。
- **未修改任何既有 HTTP 接口契约、磁盘数据结构、`.fpk` 权限位与应用标识**：
  只**新增** 3 条路由、给 `/api/compare` 与 `/api/upload/enqueue` 的响应**新增**字段
  （旧前端忽略即可）、**没有新增配置项**。**覆盖升级不会丢配置**，
  新增的 `download_queue.json` / `audit.log.jsonl` 缺失时自动创建。
- **刻意保留的保守语义**（绝不自动删除、比对只读、扫描失败必须报错、
  列不出目录 ≠ 云端没有、不可靠时不下结论、深度必须齐）都在第 4 节逐条写明并有测试钉住，
  避免被后续修改当成 bug"顺手优化"掉。
