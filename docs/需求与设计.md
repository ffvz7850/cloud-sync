## 1. 整体功能范围

### 1.1 做什么

| # | 功能 | 说明 |
|---|---|---|
| 1 | **OpenList 授权** | 地址 + 用户名 + 密码（支持 2FA）。密码换 StaticHash 登录，**不落盘明文**；token 失效自动重登 |
| 2 | **双栏文件传输** | 左栏本地目录树（聚合全部存储空间）、右栏云端目录树；勾选左侧内容上传到右侧当前目录；云端可新建文件夹 |
| 3 | **队列上传** | 持久化任务队列，并发可调；实时进度与速度；**>4MB 自动走 multipart 分片，断点续传**；应用重启未完成任务自动恢复 |
| 4 | **完整性校验** | 上传后回查云端大小比对（可关）。**不比哈希** —— OpenList 的 `hash_info` 依赖具体驱动，不可靠 |
| 5 | **失败重试** | 自动重试 + 指数退避（2s/4s/8s…，次数可调）；认证错误不重试直接判失败；耗尽后界面**手动重传** |
| 6 | **跳过已存在** | 云端同路径同大小自动跳过（可关），避免重复上传 |
| 7 | **目录对比** | 本地 vs 云端同深度递归比对，四分类：**未上传** / **大小不一致** / 已上传 / 云端独有（仅展示）；勾选批量入队 |
| 8 | **队列筛选 / 全部重试** | 每行状态彩色徽标（成功绿 / 失败红 / 进行中蓝 / 跳过灰），失败原因完整可读；按「全部 / 失败 / 已完成 / 进行中」筛选；一键**全部重试**所有失败任务（分片断点续传） |
| 9 | **状态记忆** | 记住浏览位置、对比参数、未保存的设置草稿与队列筛选，刷新 / 重开应用不丢；**绝不持久化密码 / OTP** |
| 10 | **界面** | 飞牛官方配色，接入统一网关（不占管理端口），飞牛桌面内嵌小窗 |

### 1.2 不做什么（明确划出去）

| 不做 | 原因 |
|---|---|
| **下载**云端文件到本地 | 定位是上传客户端。下载直接开 OpenList 网页或用它的 WebDAV |
| **删除 / 移动**云端文件 | 单向上传工具不碰云端已有数据，从根上杜绝误删 |
| **WebDAV 服务端** | 1.0 自带过，2.0 彻底移除 —— OpenList 自己就有 `/dav`，没必要重复造 |
| **自动同步 / 双向同步** | 这是同步软件的活。本应用只做「选、传、比」，所有上传都由人工发起 |
| **按哈希判重** | OpenList 多数驱动拿不到云端文件哈希，按路径 + 大小判断是唯一可靠口径 |

## 2. 关键设计

### 2.1 认证：StaticHash 登录（整个应用的地基）

OpenList 的密码登录**不走明文**：

```
staticHash = sha256_hex( password + "-" + "https://github.com/alist-org/alist" )
POST /api/auth/login/hash  { username, password: staticHash, otp_code }
→ { code: 200, data: { token } }
```

三个写错一个字符就连不上的点（都有测试钉住）：

1. **盐是 `alist` 旧盐**，不是 `openlist`（OpenList 为兼容沿用）；
2. token 放 `Authorization` 头是**裸值**，**没有 `Bearer ` 前缀**；
3. 错误码语义：401 密码错 / **402 需要 2FA** / 429 失败过多锁 5 分钟。

应用持久化的是 `baseUrl + username + staticHash + token`（`CredentialStore`，权限 600）。
token 失效（请求返回 401）时用 staticHash **自动重登并重放原请求一次**（带锁防并发重登）。
用户改密后 staticHash 失效，状态如实显示「连接异常」，重新登录即可。

### 2.2 上传：小文件直传，大文件分片续传

```
文件 ≤ 4MB ──→ PUT /api/fs/put（流式，File-Path 需 percent-encode）
文件 > 4MB ──→ multipart 三步：
               init → 逐块 PUT chunk（幂等、可乱序、可并发）
                    → complete 合并
               403 disabled（服务端关了分片）→ 自动降级为整文件直传
```

**断点续传的底座**是 OpenList 的 `multipart/status`：按 `path + size` 能找回
未完成的上传会话（TTL 24 小时）。会话快照里的 `received [][2]int` 是
**闭区间 [start, end]**，表示「这些分片不用再传」——客户端重传前先问一次
status，跳过已传分片，从 `frontier` 继续。闭区间语义有专门测试钉住
（展开成 done_chunks 集合后比对）。

**内存恒定**：`httpclient.put_stream` 用 `http.client` 手动 `putrequest/send`
分块发送，几 GB 的文件也不会整个读进内存。注意 `request()` 的
`_body_to_bytes` 会把 body 全读进内存，**传文件必须走 put_stream**。

**完整性校验**：上传完成后 `fs/get` 回查云端 `size` 与本地比对。
不比哈希 —— `hash_info` 由驱动决定，多数驱动不给，给了也可能口径不一。

### 2.3 上传队列：持久化状态机

```
pending ──→ uploading ──→ verifying ──→ done
   │            │  （skipExisting 命中 → skipped）
   │            ▼
   │         失败且 attempts < max → 指数退避后回 pending
   │            ▼
   │         耗尽 / AuthError → failed（界面手动重传 → 回 pending）
   └── 取消 → cancelled
```

* 队列落盘 `${TRIM_PKGVAR}/upload_queue.json`（原子写；进度 1.5s 节流落盘，状态变更立即落盘）；
* **应用重启**时把 uploading/verifying 重置为 pending —— multipart 任务会自动续传；
* N 个 daemon worker 线程（默认 2），任务内 `should_cancel` 回调响应取消；
* **锁必须是 `threading.RLock()`**：`cancel()` 在临界区里会调 `save()`，
  普通 `Lock` 不可重入直接死锁（1.0 测试真踩出来过）。

### 2.4 目录对比：四分类

本地与云端按**相同深度**递归扫描（云端用 `fs/list` 翻页拉全，`per_page` 必须 >0，
否则服务端切出空页），按相对路径对齐后分类：

| 分类 | 判定 | 去向 |
|---|---|---|
| **notUploaded** | 本地有、云端没有 | 对比结果重点标出，可批量入队 |
| **sizeMismatch** | 两边都有但大小不同 | 标出建议重传，可入队（会覆盖） |
| uploaded | 路径与大小都一致 | 计数展示 |
| cloudOnly | 云端有、本地没有 | **仅展示，不做任何处理** |

目录只比存在性（大小无意义）；入队时只取文件，目录由 `ensure_dir` 按需逐级创建。
排除规则（`*.tmp` 等通配）在本地扫描与入队展开时统一生效。

### 2.5 环境适配：飞牛裁剪 Python

飞牛自带 `python312` 是**裁剪构建**（缺 `_lzma` 等 C 扩展）。铁律：
**任何模块顶层不许硬导入依赖 C 扩展的标准库**（lzma/bz2/sqlite3/ssl/hashlib…），
必须能力探测 + 降级：

* `hasher.py`：先试 `hashlib`，没有则切内置纯 Python SHA-256（NIST 向量测试保证一致）；
* `httpclient.py`：HTTPS 时才探测 `ssl`；**内网 HTTP 走纯 `http.client`，不碰 ssl**；
* `zipfile`/`tarfile` 这类只允许在函数体内延迟 import 且必须有降级路径。
* 跨层契约测试用 AST 扫全部 server 模块的顶层 import，钉死这条铁律。

### 2.6 前端约束（飞牛 iframe 内嵌）

* **接口基地址必须实测探测**：依次试 `location.pathname` 的 `/app/<name>` 前缀、
  `/app/<appname>`、空串，对每个候选真发 `/api/info` 并校验 `d.app === "doubao-drive"`。
  只按 pathname 砍一段推导是那个"满屏 404"的经典 bug 源，测试里用**严格网关桩**
  （非本应用前缀一律 404）保证这类 bug 必挂；
* **不许用原生 `confirm/alert/prompt`**：iframe 沙箱会静默拦掉，点了完全没反应。
  全部走自绘弹层（askConfirm/askInput/askAlert）；
* **`localStorage` 必须 try/catch**：沙箱里可能直接抛 SecurityError；
* 页内不再写 `<h1>` 应用名（桌面小窗标题栏已有）；
* 飞牛官方配色变量写进 `:root` 并用测试钉住（`--fn-blue:#0f5fff` 等）。

### 2.7 布局与状态记忆（v2.1.0）

**双栏不被深路径挤坏**：`#panes` 是 `1fr auto 1fr` 网格。若两个 `1fr` 轨道与其中的 `.pane`
用默认 `min-width:auto`，目录层级越深、面包屑的 min-content 越大，网格整体右溢，随后被
`#panes{overflow:hidden}` 裁掉中栏（含 `#midbar` 与「上传 →」按钮）。约束：`.pane` /
`.pane-body` 加 `min-width:0`；`.crumb` 改 `flex-wrap:nowrap;white-space:nowrap;overflow-x:auto`
（各层级 pane-head 恒为一行）；`#midbar` 定 `min-width:118px` + `flex:none`、`#btnUpload` 加
`white-space:nowrap`。设置 / 对比页的 `.frow` 统一为 `flex-wrap:nowrap` 行栅格（label 固定宽、
控件 `flex:1;min-width:0`），窄窗口收缩不错位。均有 `test_contract.py` 的 CSS 契约断言钉住。

**UI 状态记忆**：一个 `uiState` 对象经 `ls()`（try/catch 包裹的 localStorage）落盘，写盘防抖
300ms。存：浏览位置（本地 / 云端当前目录）、对比页参数（`cmpLocal/cmpCloud/cmpDepth`）、设置草稿
（`cfg*`，点保存成功后清除并改以服务端配置为准）、队列筛选。启动时回填；记忆目录已不存在则
**降级到默认根**，不白屏。只存非敏感 UI 状态，**绝不持久化密码 / OTP**。

**一键全部重试**：`UploadQueue.retry_all()` 把所有 `failed` → `pending`（`attempts` 归零、清 `error`、
**保留 `uploaded`** 以配合 multipart 续传），只动 failed，立即落盘并唤醒空转 worker；
`POST /api/upload/retry` 带 `{"all": true}` 走该分支返回 `{"ok":true,"retried":N}`，
单条 `{"id":...}` 行为保持不变（不存在仍 404）。

## 3. 接口总览（应用自身 HTTP API）

全部在统一网关前缀 `/app/doubao-drive/api/` 下（`http_api.py` 负责前缀剥离）。
写操作一律 POST + JSON body。完整 OpenList 侧契约见 `docs/API参考.md`。

| 路由 | 方法 | 说明 |
|---|---|---|
| `/api/info` | GET | 应用标识（前端探测用，带 `app` 字段） |
| `/api/status` `/api/connection` | GET | 连接状态（online/configured/baseUrl/user） |
| `/api/connect` | POST | 登录 OpenList（baseUrl/username/password/otpCode） |
| `/api/connect/test` | POST | 分步自检（网络/登录/列目录） |
| `/api/disconnect` | POST | 清除凭据 |
| `/api/config` | GET/POST | 读写配置（并发/重试/跳过/校验/深度/排除/默认目录） |
| `/api/local/roots` | GET | 本地白名单根（聚合 `/vol*`） |
| `/api/local/list` | GET | 列本地目录（`path=` 或 `aggregate=1`），越权 400 |
| `/api/cloud/list` | GET | 列云端目录（`path=`） |
| `/api/cloud/mkdir` | POST | 云端新建目录 |
| `/api/compare` | POST | 目录对比（localRoot/cloudRoot/depth）→ 四分类 |
| `/api/upload/enqueue` | POST | 入队。两种模式：`items`（对比页，前端算好 localPath↔remotePath 映射）或 `localPaths` + `cloudDir`（传输页，后端 os.walk 展开 + 白名单校验） |
| `/api/upload/list` | GET | 任务列表 + counts（前端 1s 轮询） |
| `/api/upload/retry` | POST | 手动重传：`{"id":...}` 单条；`{"all":true}` 一键重试全部失败任务 → `{"retried":N}` |
| `/api/upload/cancel` `/remove` `/clear` | POST | 取消 / 删除单条 / 清除已完成 |
| `/api/log` | GET | 运行日志尾部 |
