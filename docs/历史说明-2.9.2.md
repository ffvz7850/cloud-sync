## 2. 本次改动清单

### 2.1 需求原文

> 当前文件对比功能的左侧面板仅支持选择本地目录，无法选择云端目录，因此无法进行云端到云端的对比。
> 请扩展该功能，使左右两侧的目录选择均同时支持本地目录与云端目录，从而支持所有对比组合：
> 本地到云端、云端到云端。要求保持现有本地目录选择与对比逻辑不变，新增的云端目录选择需与现有
> 对比流程无缝集成，并对云端目录加载失败、权限不足等异常情况进行妥善处理，确保用户可以方便地
> 切换对比来源。做成下个版本的 fpk。

需求里有两句是硬约束，决定了实现方式：

* **「保持现有本地目录选择与对比逻辑不变」** —— 所以默认组合仍是「左 = 本地、右 = 云端」，
  本地侧的白名单校验、深度收敛、父子归并、三组差异、筛选开关、批量与逐行操作**一行都没动**；
  本版只是把"哪一侧是云端"从栏位推断改成显式声明。
* **「无缝集成」** —— 所以没有另起一套比对流程：仍然是同一个 `POST /api/compare`、
  同一份响应结构、同一个差异面板。两侧的解析都在服务端完成，前端只负责把 `{side, path}` 发出去。

### 2.2 侧别由用户声明，不再由栏位推断

**改动前**：`h_compare` 只接受 `localRoot`（左）与 `cloudRoot`（右）两个路径，左必本地、右必云端。
「左侧选云端」这件事在协议里就无法表达。

**改动后**：请求体变成两侧各自声明：

```json
{ "left":  { "side": "cloud", "path": "/backup" },
  "right": { "side": "cloud", "path": "/archive" },
  "depth": 3 }
```

* `side` 的取值收敛为 `local` / `cloud`（`normalize_side()` 也认 `remote` / `openlist` / `nas` / `fs` 等别名，
  认不出来的值回退该侧的默认来源，不会因为一个拼写错误就把整次请求打成 400）；
* 响应同时回传 `left` / `right` 的 `{side, path}` —— 前端据此渲染，而不是自己记着"左边是本地"；
* **旧形状继续兼容**：只给 `localRoot` / `cloudRoot` 时等价于「左 = 本地、右 = 云端」。
  脚本、自动化、旧前端缓存不必跟着升级。

**为什么要连 `left` / `right` 一起回传**：前端曾经按栏位拼路径（左栏拼本地根、右栏拼云端根）。
两侧同构以后这个假设不再成立 —— 如果请求里两侧都声明成云端，而前端还按"左 = 本地"拼，
发出去的下载地址会指向一个不存在的本地路径。把侧别回传，前端就不需要猜。

### 2.3 每个条目带上「它自己那一侧的绝对路径」

`verify.compare()` 在产出每一条差异时补三个字段：

| 字段 | 含义 |
|---|---|
| `absPath` | 这个条目**在它自己那一侧**的绝对路径 |
| `owner` | `absPath` 属于哪一侧（`left` / `right`） |
| `peerAbsPath` | 「大小不一致」组专用：对面那一条的绝对路径 |

`owner` 是必须的，因为同一份结果里 `notUploaded` 与 `cloudOnly` 两个列表的 `absPath`
分属左右 —— 光看字段名分不出来它是"本侧"还是"对面"。

前端 `entryAbs(e, which)` 因此变成纯查表：要的是不是 `owner` 那一侧，取 `absPath`，
否则取 `peerAbsPath`。**本地侧的行为和以前完全一样**（本地条目的 `absPath` 就是它原本拼接的结果）。

### 2.4 云端目录的异常分别交代，并指明是哪一侧

以前只有一句含糊的"加载失败"。现在按原因分开，而且每条都写清是**左侧**还是**右侧**：

| 情形 | 提示 | 状态码 |
|---|---|---|
| 还没连接 OpenList | 「右侧：尚未连接 OpenList，请先在「连接」页填写地址与账号」 | 401 |
| 账号无权访问该目录 | 「右侧：云端目录无权访问（/x）」 | 401 |
| 连不上 OpenList（网络类错误） | 「右侧：连接 OpenList 失败（/x）」 | 502 |
| 云端目录不存在 | 「右侧：云端目录不存在（/x）」 | 400 |
| 该路径是文件不是目录 | 「右侧：云端路径不是目录，无法比对（/x）」 | 400 |
| 本地目录不在白名单内 / 不存在 | 「左侧：本地目录不在允许访问的范围内（…）」/「左侧：本地目录不存在或不可读（…）」 | 400 |

这两类区分是有实际意义的：**「没连上」要去「连接」页填地址，「不存在」要改路径，
「无权」要换账号** —— 它们的下一步动作完全不同，糊成一句"加载失败"等于让人猜。

根目录 `/` 不做存在性探测：它是每个存储必然存在的起点，而不同版本的 OpenList 对
`fs/get "/"` 的行为并不一致（有的返回根节点、有的报 not found）。拿一个"可能报错"的请求
去判存在性，会把能用的配置判成不能用。

前端同时把**出错那一侧**的输入框标红（不是两侧都标），用户一眼知道该改哪一格。

### 2.5 文案与按钮动词随实际来源生成

侧别可变之后，"上传 / 下载"这两个词会说不通 —— 云端↔云端时没有"上传"这回事。

* 三组分组的标题由「仅本地有 / 仅云端有 / 大小不一致」按实际侧别生成；
* 两侧**同类**（同为云端或同为本地）时加左右限定：「用右侧云端覆盖左侧云端」，
  而不是含糊的「用云端覆盖云端」；
* 行内与批量按钮的动词相应变化：本地→云端是「上传」、云端→本地是「下载」、
  同类型之间是「复制」。

默认的「左=本地、右=云端」下，界面上看到的一切文字与 2.9.1 **完全一致** —— 这是"保持原有逻辑不变"的直接体现。

### 2.6 跨侧复制：只覆盖不经队列的两种组合

新增 `POST /api/sync/copy`，把 `items`（各自侧的绝对路径）复制进 `target`：

* **`side="cloud"`（云端 → 云端）**：走 OpenList 服务端复制，同存储同步完成、跨存储由服务端建后台任务
  （任务 id 一并回传）。**按父目录分组**发送（`fs/copy` 一次可带多个 `names`），
  整组失败时**降级为逐条重试** —— 一个条目出错（目标被权限锁住、名字非法…）不该让同组其它条目陪葬，
  而且只有逐条才知道是谁失败。复制根目录 `/` 被拒绝（等于把整个存储再拷一份，必然是误操作）。
* **`side="local"`（本地 → 本地）**：走本地文件复制。目录用 `copytree(dir_exist_ok=True)`
  **合并**进目标（与云端 `overwrite=True` 的语义对齐：同名覆盖、其余保留）。
  目标目录必须在存储空间白名单内；拒绝复制存储根目录；拒绝把目标目录设进源目录内部（会无限自我复制）；
  源目录就是目标目录会被明确拒绝。
  这些校验**两趟走**：先把能判的错全判完，再动文件系统 —— 否则"目标是源的子目录"这种误操作
  一旦先建了目录，用户会凭空多出一个空文件夹，还得自己去删。

**「本地 ↔ 云端」两个方向刻意不在这里** —— 它们有断点续传、大小校验、失败重试与进度反馈，
走的是上传 / 下载队列。同一件事有两套实现，迟早会漂移。

> 这里还修掉一处会**静默叠乘**的隐患：`POST /api/compare` 的两侧扫描原本共用一份
> `localErrors`，两侧都能是本地之后，右侧的扫描错误会被当成左侧的错误上报（或反之）。
> 现在两侧各自收集。

### 3.3 端到端冒烟 —— 97 项，全绿

从 **2.9.2 的 fpk 解出来的代码**起真实 TCP 服务，对着一个**真正走 HTTP 的假 OpenList** 跑完整链路。
假 OpenList 会**严格校验请求形状**（URL 拼错、认证头不对、字段名写错立刻记入 `BAD`），
并支持真实字节下载与 `Range` 续传：

登录 → 列目录 → 诊断 → 双向比对 → 真实上传队列传文件 → 绑定创建/扫描/上传 → 任务成功后回云端核对 →
任务查不到时不得误判成功 → 源目录读不到时如实报错 → 配置收敛 → 落盘合法 → 双向比对三组精确到文件名 →

## 4. 刻意保持不变的行为

1. **默认组合不变**。不切任何开关时，左 = 本地、右 = 云端，界面文字、按钮、三组分组的
   命名与 2.9.1 **逐字一致**。
2. **本地侧的选择与比对逻辑不变**。本地目录的白名单校验、深度收敛、父子归并、
   三组差异判定、`.ddpart` 永久排除，一行都没改。
3. **绝不自动删除任何文件**。「清除」必须在用户显式点下且（批量的）二次确认之后才执行；
   没有任何定时、扫描、同步流程会触发删除。「目录绑定备份」依旧只增不删。
4. **比对本身是纯只读的**。`POST /api/compare` 不改动任何一端的文件。
5. **本地↔云端仍走队列**。断点续传、大小校验、失败重试、进度反馈一个不少 ——
   没有为了"四个方向看起来统一"而新造一条缺少这些保障的复制路径。
6. **扫描失败绝不吞掉**：某个目录列不出来时照样 `raise`，**不得悄悄少扫一层**。
7. **两边必须同深度**：深度差会把整棵子树误判成"未上传"，所以深度在扫描前统一收敛。
8. **认证头只给同源**：跨存储直链（`raw_url`）绝不附带本站令牌。
9. **旧请求形状继续兼容**：只给 `localRoot` / `cloudRoot` 会被当成默认组合，
   脚本与旧前端缓存不受影响。
10. **既有磁盘结构未改**：没有新增落盘文件，覆盖升级不丢任何配置与队列。

## 5. 已知边界与本次未做的事

- **比对只按大小，不比哈希**：两边字节数相同就判「一致」。所以「大小一样但内容不同」本版发现不了。
  这条也直接决定了「已同步」这个分组的可信度边界 —— 它是**按大小判定**的已同步。
- **本地↔本地比对没有实际使用场景之外的特殊照顾**：它天然成立（同一个白名单下的两个目录），
  复制也是普通文件复制。真要做"本地两份互为备份"的增量同步，应该用「目录绑定备份」，不是这里。
- **云端↔云端复制是"提交给服务端"**：同存储同步完成，跨存储由 OpenList 建后台任务。
  应用只回传任务 id 与已受理的条数，**不跟踪后台任务的最终成败**（OpenList 侧的任务进度
  请到它的网页界面看）。这与你直接在 OpenList 里手动复制的行为一致。
- **`same` 明细有 5000 条上限**：超出时只列出前 5000 条（界面会写明），但计数是全量真值。
- **清除不可逆、不提供撤销**。云端能否进回收站取决于 OpenList 存储驱动的配置，
  审计日志（`audit.log.jsonl`）只能记录删了什么，找不回来。
- **差异清单不自动刷新**：搬完一项该行会摘掉，但在别处（NAS 文件管理器 / OpenList 网页）
  动过的文件需要重新点一次「比对」。自动轮询比对在大库上代价太高（每次都是一次全量扫描）。
- **本次未做**：镜像同步（`full`）、移动（`move`）、WebDAV；也没有做"两侧都换成同一路径时给个警告"
  这类更进一步的防呆（本版只把误操作**拒绝掉**，不做主动猜测用户的意图）。
- **没有在真机上装过** —— 这是每次交付后的固定待办，落点是在飞牛应用中心 → 手动安装这个 fpk。

## 8. 结论

本版把比对的两侧从"栏位决定来源"改成**用户声明来源**：
每一侧都能独立选本地或云端，本地↔本地、本地↔云端、云端↔本地、云端↔云端四种组合都能比。

需求里点名的两句约束都守住了：**默认组合与全部界面文案不变**（不碰开关时和 2.9.1 逐字一致），
**本地侧的选择与比对逻辑一行没改**（白名单、深度收敛、父子归并、三组差异原样）；
云端的四种异常（未连接 / 无权 / 连不上 / 不存在或不是目录）分别给出可操作的提示并指明是左还是右。

真正的"无缝集成"体现在协议层：侧别写进请求、路径由服务端按各自来源解析、
每个条目带上**它自己那一侧**的绝对路径与归属侧别 —— 前端不必再猜"哪边是云端"，
而那个猜测正是一侧为云端时旧逻辑必然出错的地方。

**验证**：832 项全量断言 + 97 项端到端冒烟（对着解包出来的代码跑）+ 51 项打包自检 + 46 条反向验证
全部通过；包内 28 个文件与工程源码逐字节一致，`manifest.version` 与包内 `APP_VERSION` 都是 2.9.2。
