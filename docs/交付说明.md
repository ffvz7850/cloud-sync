## 1. 安装

1. 把 `doubao-drive-2.1.0.fpk` 放到你能访问的位置（如 `Z:\doubao-drive-2.1.0.fpk`，即飞牛 NAS 的共享）。
2. 飞牛 Web 端 → **应用中心 → 手动安装**（部分版本在「我的应用 → 右上角 ⋮ → 安装应用」）→ 选择该 `.fpk` → 确认安装。
3. 若提示缺少 **python312**，按提示先装它（本应用运行必需，`manifest` 里已声明 `install_dep_apps = python312`）。
4. 安装过程中会**自动执行**环境检查（`cmd/install_init`），找不到 Python 3 会直接安装失败并给中文提示。
5. 安装完成 → 飞牛桌面出现「OpenList 上传」图标。

**升级**：同 `appname` 的新包直接安装即覆盖升级，`etc/settings.conf` 与 `var/config.json`（界面里的设置）会保留，凭据 `var/credentials.json` 也会保留（需重新登录时重填一次即可）。

**安装向导**：无。`wizard/` 是空目录，安装时不会弹配置向导，所有配置都在应用界面里完成。

## 2. 首次登录（连上 OpenList）

打开应用后，未连接时**整个界面就是登录表单**（连接面板独占显示）：

| 字段 | 填什么 |
|---|---|
| 服务器地址 | OpenList 的访问地址，例如 `http://192.168.0.10:5244`。可以不带 `http://`，程序会补；末尾多写 `/` 或 `/api` 也会被规范化掉 |
| 用户名 | OpenList 的账号 |
| 密码 | OpenList 的密码 |
| 两步验证码 | 只有在 OpenList 账号**开了 2FA** 时才需要填（不填且账号开了 2FA，会返回 402 提示需要验证码） |

点「登录并连接」。成功后：

- 应用**只保存密码的哈希**（StaticHash，用于换取新的访问令牌），**不落明文密码**；前端 localStorage 里也**绝不写密码和验证码**（有测试全量扫描 localStorage 保证这一点）。
- 访问令牌（token）自动保存并在失效时自动重登续期，日常不用重复登录。
- 登录状态显示在顶栏的胶囊标记里。

常见登录失败原因见 §10 故障排查。

## 3. 日常使用（四个页面）

### 3.1 文件传输（主页面）

- **左右双栏**：左 = NAS 本地目录树，右 = OpenList 云端目录树。每栏都有面包屑（单行、可横向滚动）、刷新、新建文件夹；双击目录进入，勾选文件/文件夹多选。
- 中间的 **「上传 →」** 按钮：把左侧勾选的内容上传到**右侧当前目录**。目录会按需在云端逐级创建。
- 上传中：底部传输列表实时显示**进度条、速度、已传/总大小、状态**。
- 上传后（可关）：自动**读回云端校验大小**，不一致标为失败而不是假装成功。
- 失败：**自动重试**（指数退避，默认最多 3 次），仍失败则标记为 failed，可单条「重传」，也可点 **「全部重试」** 一键把所有失败项重新入队。
- 大文件（≥4MB）走**分片上传**，支持**断点续传**：网络中断、应用重启后未完成任务会自动继续，且**已上传的分片不会重传**。

### 3.2 目录对比

选择「本地目录 + 云端目录 + 扫描深度」，点开始对比，结果分四类：

| 分类 | 含义 |
|---|---|
| **尚未上传**（重点） | 本地有、云端没有 —— 应当上传的 |
| 大小不一致 | 两边都有但大小不同 —— 需要重传 |
| 已上传 | 两边一致 —— 无需再传，避免重复 |
| 云端独有 | 只在云端存在 —— 仅展示，**不会被删除** |

对比是**只读**的：本地与云端文件都不会被改动。勾选「尚未上传 / 大小不一致」的项目 → 加入上传队列。

### 3.3 队列区（在传输页底部）

- 状态彩色徽标：完成=绿、失败=红、进行中=蓝、跳过=灰。
- 头部统计分色显示「完成 N · 失败 N · 进行中 N」。
- 筛选按钮组：**全部 / 失败 / 已完成 / 进行中**；无匹配时显示「没有符合条件的任务」。
- 行内操作：重传（失败项）、取消（进行中）、删除（单条记录）、清除已完成。
- **「全部重试」** 按钮仅在存在失败项时出现；请求进行中会禁用，防重复点。

### 3.4 设置

- 并发数、失败重试次数、跳过云端已存在文件、上传后校验、扫描深度、排除名称规则（如 `#recycle`、`@eaDir`）、默认本地根、默认云端根。
- 「保存设置」写回服务端；下方的「查看运行日志」「断开连接」成组等宽排列。
- **状态记忆**：浏览位置（本地/云端当前目录）、对比页参数、设置页未保存草稿、队列筛选条件都会记住，刷新或重开应用不丢；记忆的目录若已不存在，会自动回退到默认根（不会白屏）。

## 4. 运行时文件与目录（NAS 上落在哪）

飞牛会把应用装到 `/var/apps/doubao-drive/`：

| 路径 | 内容 | 说明 |
|---|---|---|
| `/var/apps/doubao-drive/target/` | 程序本体 | 即安装包解出的 `app/`、`cmd/` 等 |
| `/var/apps/doubao-drive/target/app.sock` | unix socket | 网关反代入口，应用停止时会被删掉 |
| `/var/apps/doubao-drive/var/info.log` | **运行日志** | 排障第一现场，`main start/stop` 与后端输出都在这里 |
| `/var/apps/doubao-drive/var/app.pid` | 进程号 | 生命周期脚本用它判断存活 |
| `/var/apps/doubao-drive/var/config.json` | 界面里的业务配置 | 由 `/api/config` 读写 |
| `/var/apps/doubao-drive/var/credentials.json` | 凭据（地址/用户名/密码哈希/token） | 权限收紧为 600；**卸载时会被删除** |
| `/var/apps/doubao-drive/var/upload_queue.json` | 上传队列（含进度、已传分片） | 重启后据此恢复 |
| `/var/apps/doubao-drive/etc/settings.conf` | 安装级配置 | `OPENLIST_URL=`、`PYTHON=`，修改后需重启应用 |

本地开发（不在飞牛上）时，`TRIM_PKGVAR` 等环境变量不存在，数据目录回退到工程内的 `_devdata/`。

## 5. 工程文件清单（逐个说明）

源码包解压后顶层目录是 `doubao-drive-2.1.0/`。

### 5.1 包根

| 文件 | 作用 |
|---|---|
| `manifest` | 飞牛应用元数据。**INI 风格 `key = value`，不是 JSON**。含 appname / version / display_name / desc（应用中心里的长简介，支持 `<br><b>`）/ 依赖 `python312` / `desktop_uidir=ui` / `desktop_applaunchname` / 单行 `changelog` |
| `ICON.PNG` | 64×64 应用图标（fnpack 打包必须存在，尺寸会被校验） |
| `ICON_256.PNG` | 256×256 应用图标，同上 |
| `README.md` | 面向使用者的项目说明（功能、安装、使用、开发约定） |
| `config/privilege` | `{"defaults":{"run-as":"root"}}` —— 应用以 root 运行（因此能读写 NAS 上任意本地路径） |
| `config/resource` | 资源声明，当前 `{"data-share":{"shares":[]}}`，不申请额外共享目录 |
| `wizard/` | **空目录**。飞牛要求这个目录存在（官方模板就是空的）；手动往里塞 `install` 文件反而会让 `fnpack build` 校验失败 |

### 5.2 `cmd/` —— 9 个生命周期脚本（bash，必须 LF 无 BOM）

由飞牛应用中心调用，全部 `exit 0/1` 语义明确。

| 脚本 | 何时执行 | 做什么 |
|---|---|---|
| `main` | 手/系统调用 | 核心脚本：`start` / `stop` / `status` / `restart`。启动时探测 Python（优先 `/var/apps/python312/target/bin/python3`，可用 `settings.conf` 的 `PYTHON=` 覆盖）→ 以 unix socket 模式拉起 `app/server/main.py` → 写 PID、等 socket 出现；停止时 TERM→最多等 12 秒→KILL，并删 socket |
| `install_init` | 安装**前** | 环境检查：找不到 Python 3 就写出中文提示并 `exit 1`（安装失败），保证不会装上一个跑不起来的应用 |
| `install_callback` | 安装**后** | 建 `var/`、`etc/`；首次安装写入默认 `settings.conf`（`OPENLIST_URL=`、`PYTHON=`）；已有 `credentials.json` 则 chmod 600 |
| `upgrade_init` | 升级**前** | 先 `main stop`，避免文件占用 |
| `upgrade_callback` | 升级**后** | **补齐但不覆盖**新增配置项（逐项 `grep` 判断后追加），可重复执行 |
| `uninstall_init` | 卸载**前** | `main stop` |
| `uninstall_callback` | 卸载**后** | 删 socket/PID；**删除 `credentials.json`**（里面有令牌，留着没意义还危险）；业务配置保留。若安装向导选择「删除数据」，再 `rm -rf var/` |
| `config_init` | 设置页保存**前** | 先停服务，防止运行中的进程把旧配置回写覆盖新值 |
| `config_callback` | 设置页保存**后** | 用新配置重启服务 |

（脚本里统一用 `# settings.conf 是 KEY=VALUE 纯文本，值里可能带空格，不能用 source 加载` 的 `sed` 提取法读配置。）

### 5.3 `app/server/` —— 后端（纯 Python 标准库，8 个模块）

| 模块 | 行数 | 职责与关键点 |
|---|---|---|
| `main.py` | 172 | 入口。`run --socket <path>`（生产，飞牛网关）/ `run --tcp host:port`（本地调试）。启动后**恢复上传队列**（进行中任务重置为 pending，multipart 会续传）。子命令 `selftest` 做环境体检 |
| `config.py` | 245 | 版本号 `APP_VERSION`、默认配置 `DEFAULT_CONFIG`、路径解析（`data_dir()` / `etc_dir()` / `www_dir()`，按 `TRIM_*` 环境变量，缺失时回退工程内 `_devdata/`）、`load_config()` 合并 `settings.conf` 的 `OPENLIST_URL` |
| `openlist.py` | 711 | **核心**。OpenList 客户端：StaticHash 登录、token 管理、`list/get/stat/mkdir/ensure_dir/remove`、直传（流式 PUT）、multipart 分片上传（init/chunk/complete/status/abort）、断点续传、上传后校验、`diagnose()` |
| `httpclient.py` | 406 | 极简 HTTP 客户端（`http.client` 手写）。含 `put_stream()`——分块发送 + 进度回调，内存恒定（大文件不撑爆）；`request()` 会把 body 全读进内存，只用于小请求 |
| `upload_queue.py` | 420 | 上传队列与状态机、持久化（原子写 + 进度节流 1.5s、状态变更立即落盘）、N 个 worker 线程、指数退避自动重试、`retry_all()`、`threading.Event` 唤醒（入队/重试立即开工，不等轮询） |
| `verify.py` | 252 | 目录对比的四分类（**尚未上传** / 大小不一致 / 已上传 / 云端独有）、本地/云端扫描、把勾选项转成上传清单 |
| `hasher.py` | 98 | SHA-256：优先 `hashlib`，**功能性探测失败则用纯 Python 兜底**（飞牛的 python 是裁剪构建） |
| `http_api.py` | 719 | HTTP 路由与静态托管（21 条路由）。含网关前缀剥离、本地路径白名单校验、`/api/upload/enqueue` 双模式（对比模式传 `items`；浏览模式传 `localPaths` + `cloudDir`，后端负责展开目录与排除规则） |

**上传队列的状态机**：`pending → uploading → verifying → done`，另有 `failed / skipped / cancelled`。
- 自动重试：`base_delay * 2^(attempts-1)` 退避，默认最多 3 次，之后转 `failed` 等人工处理。
- 鉴权错误（`AuthError`）**不重试**，直接 failed（重试没意义，避免刷爆 OpenList 的登录限流）。
- 应用重启：`uploading` / `verifying` 一律重置为 `pending`，靠 multipart 会话续传。

### 5.4 `app/www/index.html` —— 前端（单文件，692 行）

没有构建步骤，CSS/JS 全部内联，直接用浏览器跑。要点：

- 顶栏（logo + 连接状态 + 连接按钮）+ 三个标签页：文件传输 / 目录对比 / 设置。
- 自绘弹层 `askConfirm / askInput / askAlert`（**不使用**原生 `confirm/alert/prompt`，飞牛内嵌 iframe 里体验很差且可能被拦）。
- `probeBase()`：实测探测网关前缀（校验返回的 `d.app` 是否为 `doubao-drive`），避免路径写死。
- `ls(k,v)`：localStorage 封装，**全部 try/catch**（隐私模式/沙箱禁用时静默降级）；状态记忆 key 为 `dd_ui_state`，写盘 300ms 防抖。
- 布局关键约束（v2.1.0 修的坑，勿回退）：`#panes{grid-template-columns:1fr auto 1fr}`、`.pane/.pane-head/.pane-body{min-width:0}`、`.crumb{flex-wrap:nowrap;overflow-x:auto}`、`#midbar{flex:none;min-width:118px}`、`#btnUpload{white-space:nowrap}`。
- 配色使用飞牛变量（`--fn-blue:#0f5fff` 等），不引入外部 CSS/字体/图标库。

## 6. 架构与关键数据流

```
浏览器 / 飞牛桌面 iframe
        │  (统一网关 /app/doubao-drive，前缀由 http_api.strip_prefix 剥掉)
        ▼
   unix socket app.sock
        ▼
   app/server/main.py  ──► http_api.AppHandler（21 条路由）
        │                        │
        │                        ├─ openlist.OpenlistClient ── HTTP ──► OpenList :5244
        │                        │       ├─ 直传 PUT /api/fs/put（<4MB）
        │                        │       └─ 分片 /api/fs/multipart/*（≥4MB，可续传）
        │                        ├─ upload_queue.UploadQueue（worker 线程池 + 持久化）
        │                        └─ verify（本地/云端递归扫描 + 四分类）
        └─ var/upload_queue.json（队列与进度，原子写）
```

**上传一条任务的完整路径**：前端勾选 → `POST /api/upload/enqueue`（对比模式直接给映射；浏览模式给本地路径，后端展开并过滤）→ 队列落盘 → worker 取任务 → 跳过已存在（可关）→ 云端逐级 `ensure_dir` → 上传（小文件直传 / 大文件分片，带进度回调）→ 上传后按大小校验 → 标记 `done`；失败按退避重试，耗尽转 `failed` 等「全部重试」。

**鉴权要点（写错一个字符就连不上）**：
- StaticHash 公式：`sha256_hex(password + "-" + "https://github.com/alist-org/alist")` —— 盐是 **alist 的旧盐**，不是 openlist。
- 登录：`POST /api/auth/login/hash` → `{code:200, data:{token}}`。
- 请求鉴权：`Authorization: <token>` 是**裸值，没有 `Bearer` 前缀**。
- 收到 401 时用保存的 StaticHash 自动重登并重试原请求一次。

## 7. 开发铁律（踩过的坑，别重犯）

1. **飞牛自带的 python312 是裁剪构建**（缺 `_lzma`、可能缺 `_ssl`）。后端**任何模块都不许顶层硬导入依赖 C 扩展的标准库**（`lzma/bz2/gzip/zlib/zipfile/tarfile/sqlite3/hashlib/ssl/ctypes`）——要走能力探测 + 降级。`test_contract.py` 用 AST 检查守着这条。
2. **内网 HTTP 别依赖 ssl**：上传走 `http.client` 手写流式发送，绕开 `_ssl` 缺失问题。
3. **大文件不要读进内存**：`httpclient.request()` 会把 body 全读进内存，只用于小请求；文件一律走 `put_stream()`。
4. **`threading.Lock` 不可重入**：队列里曾经在持锁时调用同样要加锁的 `save()` → 死锁挂死。现在用 `RLock`，并把 `save()` 移出临界区。
5. **CSS Grid 用 `1fr` 装可伸缩内容必须显式 `min-width:0`**：否则内容的 min-content 会撑破轨道；配合 `overflow:hidden` 就变成"元素凭空消失"（v2.0.1/v2.1.0 的「上传按钮不见了」就是这个）。
6. **mock 只匹配路径会掩盖 URL 构造 bug**：假传输层按 path 子串匹配，结果首次登录时相对 URL 报 `unknown url type` 都没测出来。关键请求要断言**完整 URL**。
7. **飞牛网关前缀**：所有前端请求路径都要经 `probeBase()`/`strip_prefix` 处理，别写死 `/api/...` 的绝对根路径。
8. **manifest 是 INI 不是 JSON**；`cmd/` 脚本必须 **LF、无 BOM**（否则 NAS 上 `bad interpreter`）。
9. **升级绝不改 `appname`**。
10. **网络盘（Z:）写入只创建新文件名**：不要覆盖/重命名/删除已存在的文件。

## 10. 故障排查

| 现象 | 原因 / 处理 |
|---|---|
| 应用中心点击图标打不开 / 白屏 | 看 `/var/apps/doubao-drive/var/info.log`。常见：Python 未找到（`install_dep_apps` 的 python312 没装上）、`app.sock` 未创建（后端启动即崩） |
| 应用中心里"应用未运行" | `cd /var/apps/doubao-drive/target && ./cmd/main status`（0 在跑，3 没跑）；`./cmd/main restart`；再看 info.log |
| 登录报 401 | 用户名或密码不对。注意 StaticHash 用的是 alist 旧盐，若自行改过 `openlist.py` 的 `STATIC_HASH_SALT` 必登不上 |
| 登录报 402 / 提示需要验证码 | OpenList 账号开了 2FA，在登录表单填「两步验证码」 |
| 登录报 429 | 密码错太多次触发了限流（OpenList 默认锁 5 分钟），等待后重试，别连续试 |
| 连不上服务器 | 地址是否可达（在内网用 NAS 的 IP，而不是 `127.0.0.1`；本应用与 OpenList 同机时用 `192.168.x.x` 亦可）；OpenList 是否禁用了游客（本应用是登录后访问，不影响） |
| 云端列目录报错 | OpenList 侧该存储驱动异常时，`fs/list` 会返回错误，界面上会原样提示；先去 OpenList 后台确认该存储可用 |
| 上传一直失败并自动重试 | 看队列行的错误详情。若 OpenList 侧 multipart 被禁用（返回 403 disabled），客户端会**自动降级为直传**；权限不足则提示 business 错误 |
| 上传按钮看不到（老版本） | v2.0.1 及更早的布局缺陷，升级到 2.1.0 |
| 大文件传到一半断了 | 直接用「重传」或「全部重试」，会从已传分片继续；应用重启后队列也会自动接着传 |
| 想确认上传是否真成功 | 队列状态 `done` 表示**上传后又读回云端比对过大小**；也可用「目录对比」复查 |
| 界面记住的目录不存在了 | 会自动回退到默认根，不会白屏；在设置页改默认根即可 |
| 需要 WebDAV 挂载 | 本应用不提供 WebDAV（v2.0.0 起已彻底移除）。**直接用 OpenList 自带的 `/dav`** 接口挂载 |
