## 2. 本次改动清单

### 2.1 需求原文

> 对比列表条目过多，不便统一处理。请将对比列表中"仅本地"、"仅云端"、"大小不一致"、"已同步"
> 这一状态列的图标改为可点击的筛选开关：点击某个图标后，列表仅显示对应分类的条目，便于按分类
> 集中处理；再次点击则取消筛选，恢复完整列表。图标需具备清晰的选中/未选中视觉状态，筛选切换
> 应即时生效。请保留原有图标的分类含义不变，并确保该筛选功能与列表其他操作（如排序、单条处理）
> 互不影响。

### 2.2 状态标签变成筛选开关

`#diffHead` 里的四个统计标签由 `<span>` 改成 `<button>`，各自带 `data-filter`：

| 标签 | 点一下的效果 |
|---|---|
| 仅本地 | 只显示「本地有、云端没有」的条目 |
| 仅云端 | 只显示「云端有、本地没有」的条目 |
| 大小不一致 | 只显示「两边都有但大小对不上」的条目 |
| 已同步 | 只显示「两边大小一致」的文件（只读分组，详见 2.4） |

- **再点一次取消**：同一枚标签点第二次即恢复完整列表（默认显示三组差异）。
- **互斥切换**：直接点另一枚就切过去，不会叠加两个筛选。
- **即时生效**：切换是纯前端重绘，**不重新请求后端**（测试里直接断言比对请求数没变）。
  一次比对动辄几秒到几十秒，如果切个筛选就重扫一遍，这个功能等于没用。
- **选中态给了四重信号**：底色 + 描边 + 字重加粗 + 末尾的 ✓，并且带 `aria-pressed`。
  **不靠颜色单独区分** —— 色弱用户也要能看出哪一枚是按下的。
- **分组头一律渲染**：筛到某一类时哪怕它是空的，也会画出分组头并写明「这一类当前没有条目」。
  否则用户点了一枚标签、界面毫无变化，会以为功能坏了。
- **数字为 0 的标签照样可点**（只是视觉上淡化），不禁用 —— 点了看到"0 项"是明确反馈，
  一个点不动的按钮只会让人怀疑坏了。

### 2.3 筛选不影响任何其它操作

这是需求里明确点名的约束。实现上靠一件事保证：**筛选只改渲染，不改状态**。

- **勾选不会掉**：选中集合 `diffState.sel` 按 `kind|path` 存，跟"当前显示哪些行"完全无关。
  筛到其它分组、再筛回来，勾选的还是原来那些。
- **单条操作照常可用**：筛选态下行的「上传 / 下载 / 清除本地 / 清除云端 / 用本地覆盖 / 用云端覆盖」
  全部正常工作（测试里在筛选态下真的点了一次「下载」并断言请求发对了）。
- **「全选」按当前可见范围取值**：筛出「仅本地」本来就是为了集中处理它，此时全选**只勾这一组**，
  不会把看不见的其它组的行一起勾上。没筛选时全选 = 三组差异全部。
- **「清空勾选」仍是全局清空**（不受筛选影响），符合"清空"这个词的直觉。
- **顺序不变**：筛选不重新排序，列表顺序与后端返回的 `sorted()` 结果一致。

### 2.4 「已同步」首次有明细可看

之前「已同步」只是个数字（`uploadedFiles + uploadedDirs`），筛不出任何东西 ——
点下去会得到一个空列表，这本身就像个 bug。所以本次让后端也回明细：

- `verify.compare()` 新增 `uploaded` 明细（受 `UPLOADED_LIMIT = 5000` 上限约束）+ `uploadedTruncated` 标记；
- `split_diff()` 新增第四组 `same` / `sameCount` / `sameListed`；
- 前端把它渲染成**只读分组**：没有勾选框、没有操作按钮、没有「全选本组」，
  筛到它时「全选」按钮直接禁用（并给出 `title` 说明原因）。

**两条刻意的规则**：

1. **只列文件，不列目录**。目录的"已同步"只代表两边都存在这个路径，**不代表里面的文件都传完了**
   （子文件可能整批还没上传）。把这种目录列成"已同步项"，用户会以为已经齐了 —— 这是误导。
   两边都存在的目录数在分组头里单独交代（「另有 N 个目录两边都存在（路径存在≠内容齐全，不逐条列出）」）。
2. **不归并父子项**。`_prune_descendants` 是为"批量去重"服务的（目录已列为差异项时不再单列子项），
   而「已同步」不参与任何批量操作 —— 套上归并只会让明明同步了的子文件凭空消失。

### 2.5 「已同步」计数口径的修正

徽标上「已同步」的数字从 `uploadedFiles + uploadedDirs` 改成**只算文件数**。

原因很直接：标签点下去看到的是**文件列表**，如果数字是"文件 + 目录"，就会出现
"说有 300 项、点开只有 250 条"这种对不上的情况。而目录路径存在本身就不等于内容同步，
把它算作已同步是旧口径的一个瑕疵。目录数在分组头里给了明文交代，信息没有丢。

### 2.6 截断：明细可以少给，数字绝不许缩水

`UPLOADED_LIMIT = 5000`。超出时：

- 明细截断到 5000 条，`uploadedTruncated = true`，分组头写明「共 N 项，仅列出前 5000 条」；
- **`sameCount` 始终是 `compare()` 算出的全量真值**，不是 `len(same)` —— 否则备份目录一大，
  徽标数字会悄悄变小，用户拿到的就是错的数字；
- **不给 `sameBytes` 字段**：截断后按剩下的明细求和是错的，宁可没有。

这条规则前后端各有一条测试钉着，反向验证里也有两条变异专门盯它。

## 4. 刻意保持不变的行为

1. **绝不自动删除任何文件**。「清除」必须在用户显式点下且（批量的）二次确认之后才执行；
   没有任何定时、扫描、同步流程会触发删除。「目录绑定备份」依旧只增不删。
2. **比对本身是纯只读的**。`POST /api/compare` 不改动任何一端的文件，
   改动只发生在用户点了「上传 / 下载 / 清除」之后。
3. **扫描失败绝不吞掉**：某个目录列不出来时照样 `raise`，**不得悄悄少扫一层**。
4. **两边必须同深度**：深度差会把整棵子树误判成"未上传"，所以深度在扫描前统一收敛。
5. **认证头只给同源**：跨存储直链（`raw_url`）绝不附带本站令牌。
6. **`.ddpart` 永久排除**：不受用户排除规则配置影响（用户在设置里清空规则也不影响）。
7. **既有接口契约与磁盘结构未改**：本版没有新增路由、没有新增落盘文件，
   覆盖升级不丢任何配置与队列。
8. **筛选状态不持久化**：不写 localStorage，刷新后回到"全部显示"。
   默认就是最干净的状态（三组差异、不铺开已同步），不需要用户去猜上次筛了什么。

## 5. 已知边界与本次未做的事

- **比对只按大小，不比哈希**：两边字节数相同就判「一致」。所以「大小一样但内容不同」本版发现不了。
  这条也直接决定了「已同步」这个分组的可信度边界 —— 它是**按大小判定**的已同步。
- **`same` 明细有 5000 条上限**：超出时只列出前 5000 条（界面会写明），但计数是全量真值。
  如果确实需要逐条浏览全部已同步文件，应该用 NAS 文件管理器或 OpenList 网页，
  而不是让一次比对回传几万条。
- **「已同步」不列目录**：见 2.4 —— 目录路径存在不等于内容齐全，列出来是误导。
  需要确认某个目录是否真的传全了，看「仅本地」组里有没有它的子文件即可。
- **清除不可逆、不提供撤销**。云端能否进回收站取决于 OpenList 存储驱动的配置，
  审计日志（`audit.log.jsonl`）只能记录删了什么，找不回来。
- **差异清单不自动刷新**：搬完一项该行会摘掉，但在别处（NAS 文件管理器 / OpenList 网页）
  动过的文件需要重新点一次「比对」。自动轮询比对在大库上代价太高（每次都是一次全量扫描）。
- **本次未做**：镜像同步（`full`）、移动（`move`）、WebDAV；也没有做"按文件名/类型搜索"这类
  更进一步的过滤（本版只做分类筛选，是需求明确的范围）。
- **没有在真机上装过** —— 这是每次交付后的固定待办，落点是在飞牛应用中心 → 手动安装这个 fpk。

## 8. 结论

本版把差异结果的四个状态标签从"只能看的统计"变成了**筛选开关**：
点一下只看这一类、再点恢复全部，选中态用四重信号表达，切换纯前端重绘、立即生效。

需求里点名的"互不影响"是设计上的第一约束：筛选只改渲染、不改状态 ——
勾选按条目身份保存，筛来筛去不会掉；单条操作在筛选态下照常可用；
「全选」按当前可见范围取值，不会勾上你看不见的行。

顺带把一个一直存在的粗糙处修了：「已同步」以前只有一个数字，点下去什么都看不到；
现在它是只读分组，逐条列出两边大小一致的文件，并明确了"只算文件、目录单独交代""计数永远是全量真值"这两条口径。

**验证**：755 项全量断言 + 78 项端到端冒烟（对着解包出来的代码跑）+ 51 项打包自检 + 26 条反向验证
