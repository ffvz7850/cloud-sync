# 交接说明 —— 云端互传（`cloud-sync`）

> 这份文档写给**接手这个工程的 AI 或人**。目标：读完就能跑测试、能改代码、能打包、不踩已知的坑。
> 当前版本 **2.15.40**，飞牛 fnOS 原生应用（`.fpk`），本机开发在 Windows 上完成、部署到 ARM/x86 NAS 上运行。

## 0. 一页速览

| 项目 | 值 |
|---|---|
| 应用名 / id | 云端互传 / `cloud-sync` |
| 版本 | `manifest` 的 `version` 与 `app/server/config.py` 的 `APP_VERSION`（**两处必须一致**） |
| 形态 | 飞牛 fpk 应用：Python 3 后端（纯标准库）+ 单个 HTML 前端 + 飞牛生命周期脚本 |
| 后端 | `app/server/*.py`，纯标准库，无第三方依赖 |
| 前端 | `app/www/index.html`，单文件（HTML + CSS + JS 全内联，**没有构建步骤**） |
| 入口 | 飞牛统一网关 Unix Socket，经 `/app/cloud-sync/**` 转发；本机开发可退到 TCP 端口 |
| 对接 | OpenList 服务端（聚合豆包 / 阿里 / 百度 / 天翼等网盘） |
| 测试 | `python tests/run_all.py`（Python 单测 + jsdom 前端断言） |
| 打包 | `python tools/build_fpk.py --project .` → `dist/cloud-sync.fpk` |
| 源码包 | `python tools/pack_src.py --out dist/cloud-sync-<版本>-src.zip` |

## 1. 30 秒上手

所有命令在**工程根目录**（含 `manifest` 的那一层）执行：

```bash
# 1) 全部单元测试 + 前端断言（Python unittest + jsdom 真跑页面脚本）
python tests/run_all.py

# 2) 打包成 fpk
python tools/build_fpk.py --project . --fnpack tools/fnpack.exe

# 3) 打源码交接包
python tools/pack_src.py --out dist/cloud-sync-<版本>-src.zip
```

环境要求：

- **Python 3.8+**。用 `sys.executable` 跑测试，不需要额外配置。
- **Node.js**（仅前端测试需要，要能 `require('jsdom')`）。找不到 jsdom 时：

  ```bash
  npm i jsdom                                    # 任意目录
  DD_NODE_PATH=<那个目录>/node_modules python tests/run_all.py
  DD_NODE=/path/to/node python tests/run_all.py  # 找不到 node 时显式指定
  ```

- **fnpack**（飞牛官方打包 CLI）：已放 `tools/fnpack.exe`（Windows 版）。

**本机起服务调试**（不装 NAS 也能看界面）：

```bash
python app/server/main.py --tcp 127.0.0.1:8380
# 浏览器打开 http://127.0.0.1:8380/
```

## 3. 关键设计

- **所有网络交互都收敛在 `openlist.py`**，出问题改这一处。
- **所有接口都在 `http_api.py` 的 `_ROUTES` 里**，加接口改这里（`tests/test_contract.py` 会核对）。
- **同步备份（bindings.py）**：源目录 → 多个云端目标，增量扫描只找缺失文件，
  上传走 OpenList 服务端复制。冲突策略：跳过已存在（默认）/ 覆盖 / 中止。
  自动扫描：每隔 N 天（默认 7 天）在指定时间点全量扫描；全局扫描并发限制避免挤爆服务器。
- **传输列表**：上传 + 下载 + OpenList 服务端复制同列一表，状态直接引用 OpenList 服务端任务，
  分页展示，支持全部暂停/取消/清除已结束/全部重试。
- **上传进行中禁止扫描**（2.15.39 新增）：后端 `can_scan()` 闸门 + 前端按钮禁用，
  避免扫描把正在复制的文件判成缺失导致重复上传。

## 4. 开发铁律

1. **飞牛的 Python 是裁剪构建**——禁止顶层硬导入依赖 C 扩展的标准库
   （`lzma` `bz2` `gzip` `zlib` `zipfile` `tarfile` `sqlite3` `hashlib` `ssl` `ctypes`）。
   需要时做**能力探测 + 降级**（参考 `hasher.py` / `httpclient.py`）。
2. **`cmd/*` 必须 LF 换行、无 BOM、有可执行位**。CRLF → `bad interpreter`；
   BOM → 起不来；无可执行位 → `Permission denied`。用 `tools/build_fpk.py` 打包（它补权限）。
3. **每次改动都要迭代版本号**，动两处：`app/server/config.py` 的 `APP_VERSION`、
   `manifest` 的 `version`。两个平台（x86/arm）各有一份 fpk 打包目录。
4. **不可逆操作必须有白名单 + 审计**（删除/覆盖前全部校验 + 界面二次确认 + 写审计日志）。
5. **`.ddpart` 临时文件永久排除**：下载先写 `<目标>.ddpart` 再原子改名，所有扫描比对里排除。

## 6. 改代码的标准流程

```
1. 定位            改哪层：接口 http_api.py，业务 openlist.py/verify.py/bindings.py，界面 index.html
2. 改代码          遵守 §4 铁律
3. 补测试          改后端 → test_*.py；改界面 → test_ui.js / test_bindings_ui.js
4. 跑全量          python tests/run_all.py        必须全绿
5. 升版本          config.py + manifest（version）
6. 打包            python tools/build_fpk.py --project . --fnpack tools/fnpack.exe
7. 打源码包        python tools/pack_src.py --out dist/cloud-sync-<版本>-src.zip
```

## 8. 常见坑速查

| 症状 | 原因 | 处置 |
|---|---|---|
| 应用装上起不来，`status` 返回 1，日志全空 | `cmd/*` 没有可执行位（Windows 上 fnpack 打出 0666） | 用 `tools/build_fpk.py` 打包，别直接调 fnpack |
| NAS 上 `bad interpreter` | `cmd/*` 是 CRLF 或带 BOM | 转 LF、去 BOM（自检会拦） |
| 后端启动报 `ModuleNotFoundError: _lzma` 等 | 顶层硬导入了依赖 C 扩展的标准库 | 改成能力探测 + 降级，见 §4 |
| 前端测试报 `Cannot find module 'jsdom'` | 没有 jsdom 或路径没指对 | `DD_NODE_PATH` 指到含 node_modules 的目录 |
| 打包报「缺少 wizard/」 | 空目录没被打进去 | 用 `tools/pack_src.py`，它会显式写空目录条目 |

祝顺利。这个工程最大的敌人是飞牛那个**裁剪过的 Python** 和**「测过了」与「真发出去的那份」之间的缝隙**。
